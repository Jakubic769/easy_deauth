# Easy WiFi Lab

> A lightweight Python CLI for building and testing an **authorized wireless security lab**.

Easy WiFi Lab is a terminal-based Wi-Fi laboratory tool designed for learning how wireless discovery works in a controlled environment.

It provides a clean workflow for:

* Selecting a Wi-Fi adapter
* Switching the adapter into monitor mode
* Performing a short passive wireless scan
* Parsing `airodump-ng` CSV output
* Displaying discovered access points and stations
* Selecting a laboratory access point
* Selecting an associated station
* Validating targets against an explicit lab allow-list
* Restoring the adapter to managed mode when the program exits

The project uses **Python + Rich** for a simple but polished terminal interface.

---

## ⚠️ Important

**This project is intended only for networks, devices, and wireless environments that you own or have explicit permission to test.**

Do not use it to interfere with networks belonging to other people.

The current version intentionally **does not automate Wi-Fi deauthentication or provide a generic `aireplay-ng -0` launcher**. Active wireless testing should only be performed in an environment where you have explicit authorization.

The target-selection workflow is protected by an allow-list so that only configured laboratory access points can be selected.

# ✨ Features

### Wi-Fi adapter selection

The application automatically discovers available wireless interfaces using `iw`.

```text
Wi-Fi interfaces

┏━━━┳━━━━━━━━━━┓
┃ # ┃ Interface┃
┡━━━╇━━━━━━━━━━┩
│ 1 │ wlan0    │
│ 2 │ wlan1    │
└───┴──────────┘

Select an interface:
```

---

### Monitor mode

The selected adapter can be switched into monitor mode directly from the application.

The application also attempts to restore the adapter to managed mode when it exits.

---

### Passive scanning

The scanner uses `airodump-ng` to passively observe nearby wireless traffic for a configurable period.

The default scan duration is:

```text
15 seconds
```

No active attack traffic is generated by the scanner.

---

### Rich terminal interface

The interface is built with [Rich](https://github.com/Textualize/rich).

It provides:

* Tables
* Panels
* Colors
* Interactive prompts
* Status messages
* Clear validation results

Example:

```text
╭────────────────────────────╮
│       TARGET VALIDATED     │
│                            │
│ AP: AA:BB:CC:DD:EE:01      │
│ Channel: 6                 │
│ Station: 11:22:33:44:55:66 │
╰────────────────────────────╯
```

---

### AP and station discovery

After scanning, the application separates:

```text
Access Points
      │
      ├── BSSID
      ├── Channel
      ├── Signal
      └── ESSID

Stations
      │
      ├── MAC address
      ├── Associated BSSID
      └── Signal
```

---

### Laboratory allow-list

Targets must belong to an explicitly configured laboratory environment.

The allow-list is stored in:

```text
config.json
```

Example:

```json
{
  "allowed_bssids": [
    "AA:BB:CC:DD:EE:01"
  ]
}
```

An AP that is detected but isn't in this list cannot be selected as a laboratory target.

# 📦 Installation

## Linux

Clone the repository:

```bash
git clone https://github.com/YOUR_USERNAME/easy-deauth-lab.git
cd easy-deauth-lab
```

Create a virtual environment:

```bash
python3 -m venv .venv
```

Activate it:

```bash
source .venv/bin/activate
```

Install Python dependencies:

```bash
pip install -r requirements.txt
```

Install the system dependencies:

```bash
sudo apt update
sudo apt install -y python3 python3-venv python3-pip iw aircrack-ng
```

sudo .venv/bin/python main.py

# 🪟 Windows / WSL

The repository contains:

```text

```

and:

```text

```

These provide a Windows-side entry point for a WSL-based Linux installation.

For reliable monitor-mode laboratory work, a compatible external USB Wi-Fi adapter and an appropriate Linux environment are recommended.

# ⚙️ Configuration

The main configuration file is:

```text
config.json
```

Example:

```json
{
  "allowed_bssids": [
    "AA:BB:CC:DD:EE:01",
    "AA:BB:CC:DD:EE:02"
  ]
}
```

Add the BSSID of your own laboratory access point.

For example:

```text
MyLab
└── AA:BB:CC:DD:EE:01
```

Only BSSIDs listed in `allowed_bssids` are considered valid laboratory targets.

# 📚 Module overview

## `main.py`

Application entry point.

Responsible for:

* User interaction
* Menu flow
* Displaying tables
* Selecting interfaces
* Selecting APs
* Selecting stations
* Coordinating the other modules

---

## `wifi_lab/interfaces.py`

Handles wireless interfaces.

Responsibilities:

```text
iw dev
```

Interface discovery:

```python
list_wifi_interfaces()
```

Monitor mode:

```python
enable_monitor_mode(interface)
```

Managed mode restoration:

```python
restore_managed_mode(interface)
```

---

## `wifi_lab/scanner.py`

Responsible for launching the passive scanner.

It executes `airodump-ng` for the configured scan duration and returns the generated CSV file.

Default:

```python
scan(interface, seconds=15)
```

---

## `wifi_lab/parser.py`

Converts `airodump-ng` CSV output into Python objects.

The parser produces:

```python
list[AccessPoint]
list[Station]
```

This keeps the rest of the application independent from the raw CSV format.

---

## `wifi_lab/models.py`

Contains the data structures used by the application.

### AccessPoint

```python
@dataclass
class AccessPoint:
    bssid: str
    channel: str
    signal: str
    essid: str
```

### Station

```python
@dataclass
class Station:
    mac: str
    bssid: str
    signal: str
```

---

## `wifi_lab/lab.py`

Handles laboratory target validation.

The important rule is:

```text
Detected target
      │
      ▼
Is BSSID in config.json?
      │
   ┌──┴──┐
  YES    NO
   │      │
   ▼      ▼
 ALLOW   BLOCK
```

This prevents an arbitrary detected AP from becoming an accepted lab target.

# 🔐 Safety model

Easy WiFi Lab follows a simple principle:

> **Discovery can be broad; active testing must be explicitly scoped.**

The application can discover nearby wireless networks during passive scanning.

However, the application only considers an AP valid for the laboratory workflow when its BSSID appears in:

```text
config.json
```

This provides an explicit boundary between:

```text
Wireless discovery
```

and:

```text
Authorized laboratory testing
```

# 🛠️ Troubleshooting

## `iw: command not found`

Install `iw`:

```bash
sudo apt install iw
```

---

## `airodump-ng: command not found`

Install Aircrack-ng:

```bash
sudo apt install aircrack-ng
```

Verify:

```bash
airodump-ng --help
```

---

## No Wi-Fi interfaces detected

Check:

```bash
iw dev
```

If nothing appears, Linux may not have access to your wireless adapter.

Check:

```bash
ip link
```

and:

```bash
lsusb
```

For a USB adapter, verify that the device is visible to the operating system.

---

## Monitor mode does not work

Not every Wi-Fi adapter supports monitor mode properly.

Check the adapter and driver:

```bash
iw list
```

Look for supported interface modes.

A compatible external USB Wi-Fi adapter is usually the easiest option for a dedicated wireless lab.

---

## NetworkManager interferes with monitor mode

Some Linux configurations automatically manage wireless interfaces.

If monitor mode immediately disappears or behaves unexpectedly, inspect:

```bash
systemctl status NetworkManager
```

Avoid blindly disabling networking on a machine that you depend on for connectivity. Prefer using a dedicated laboratory adapter.

# 🧪 Recommended laboratory setup

For learning wireless security safely, use a dedicated environment:

```text
                 Your Computer
                       │
             ┌─────────┴─────────┐
             │                   │
        Wi-Fi Adapter        Lab Router
        (monitor mode)       "MyLab"
             │                   │
             │              Test Device
             │
             └──── Authorized Lab ────┘
```

Ideally:

* Use a router you own.
* Use test devices you control.
* Use a separate SSID for the lab.
* Keep the lab isolated from production networks.
* Use a dedicated USB Wi-Fi adapter.
* Keep the AP BSSID in `config.json`.

# ⭐ Project goal

Easy WiFi Lab is intended to make wireless-security experimentation easier to understand by exposing the workflow step by step:

```text
Adapter
   ↓
Monitor Mode
   ↓
Passive Scan
   ↓
Parse Results
   ↓
Select Lab AP
   ↓
Select Station
   ↓
Validate Authorization
   ↓
Controlled Laboratory Testing
```

The goal is not to hide what happens behind a single command, but to provide a small, understandable codebase that can be extended while keeping the laboratory boundary explicit.
